# Deployment handoff

No live deployment was performed. Use your own repository/accounts and configure secrets before enabling deployment. Never commit private .env files. External host plans and limits must be checked with the chosen provider.

1. Push the extracted source to your repository. Run CI. Create CE-2/ETE tags only after the corresponding acceptance checks pass.
2. Provision MongoDB Atlas with a database user limited to this database and an appropriate network allow-list. Set MONGODB_URI. Transactions require a replica set.
3. Deploy backend from backend/Dockerfile or `npm ci --omit=dev && npm start`. Set NODE_ENV=production, JWT_SECRET, MONGODB_URI, CLIENT_ORIGIN (exact frontend origin), PORT, UPLOAD_DIR on a persistent disk, and optional REDIS_URL (use TLS URL where required). Seed once using your chosen admin environment variables. Remove seed password from runtime configuration afterwards if no longer needed.
4. Deploy payment-service with API_URL and a distinct random PAYMENT_SERVICE_SECRET shared with the API; set API PAYMENT_SERVICE_URL. Put service-to-service traffic on a private network where supported. Production mode intentionally disables mock payments; use COD for production smoke checks or a separate non-production demo environment for simulated payments.
5. Build frontend with `npm ci && npm run build` and VITE_API_URL=https://your-api.example/api. Set SPA fallback to index.html (provided Netlify _redirects and Vercel rewrite). Upload image URLs derive from the API origin. Keep secrets out of VITE variables.
6. A gateway deployment can instead use a single public origin and the nginx routing configuration. Configure HTTPS at the hosting edge, persistent image storage, authenticated database/Redis, firewall and backups. The supplied Compose file is for local evaluation, not hardened public hosting.
7. GitHub workflow tests and builds on pushes and pull requests. Optional deploy job is gated on main plus repository variable ENABLE_DEPLOY=true and the production environment. Configure protected environment approval and BACKEND_DEPLOY_HOOK / FRONTEND_DEPLOY_HOOK secrets for your host. Configure service deployment through its host repository integration. Deploy hooks trigger host jobs; they do not prove successful rollout. Review host logs and smoke-test afterwards.
8. Acceptance: register a customer, search, review, add cart item, place COD order, verify ownership, sign in as admin, upload product image and advance order status. Refresh a nested URL. Verify health, request IDs, Redis MISS/HIT and invalidation. Record live URLs, CI run and actual results in TESTING.md.
