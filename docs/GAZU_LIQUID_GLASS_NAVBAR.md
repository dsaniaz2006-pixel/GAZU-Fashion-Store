# GAZU — Nimbus Liquid Glass Navbar integration

## Reference and placement

The supplied video demonstrates a compact horizontal glass pill on a pale-blue background. A water-like active selection travels between icons, stretches across longer jumps, produces small merging droplets, and falls back to a translucent CSS bubble when WebGL is unavailable. The demo contains **Home, Explore, Flights, Weather and Profile**. Those demo destinations do not exist in GAZU.

This integration inserts the original **Nimbus UI Waterline** component into GAZU's **existing header's primary desktop navigation**. It retains the centered GAZU wordmark, all user/wishlist/bag/search/admin controls, the existing hamburger navigation on smaller screens, and all prior homepage animation sections. It does not create a second header or an unrelated floating navigation strip.

### Actual GAZU routes

| Pill | Destination |
| --- | --- |
| HOME | `/` |
| MEN | `/shop?category=Men` |
| WOMEN | `/shop?category=Women` |
| KIDS | `/shop?category=Kids` |
| SHOP | `/shop` |
| STORY | `/about` |

The active pill follows `useLocation()` including the shop category query parameter. Selecting an item calls the existing StorefrontContext `go()` helper, so navigation stays within React Router without a full-page reload. On other pages (cart, account, product, admin) no primary item is selected.

## Structure and dependency audit

- Existing stack is **Vite + React 19 + JavaScript/JSX**, plus `@tailwindcss/vite` and Tailwind CSS v4, Lucide React, React Router, GSAP.
- It was **not** a fully initialized shadcn/ui TypeScript project. The provided Waterline widget is self-contained and has no dependency on shadcn primitives, so installing shadcn or rewriting the app in TypeScript would add risk without helping the navbar. Creating `src/components/ui` follows the shadcn/shared-component convention while preserving the current app.
- Vite's built-in esbuild pipeline supports imported `.tsx` files. A `tsconfig.json` is included to make the new TSX path explicit. To perform full TypeScript type checking (optional), install the TypeScript compiler and React type packages when network access is available: `npm install -D --prefix frontend typescript @types/react @types/react-dom`. This is not needed for Vite TSX transpilation.
- To initialize shadcn for future shadcn components, run `npx shadcn@latest init` from `frontend/` after reviewing the changes it proposes. **Not necessary for this navbar.**
- All existing dependencies were reused; **no new runtime dependencies were introduced**.
- No images were requested by this component; the SVG icons are generated by React/Lucide, and the water effect is drawn by WebGL/CSS. No unnecessary Unsplash imagery was added.

## Behaviour

- The liquid drop follows active route selection and plays the original spring/droplet ripple animation.
- It uses WebGL when available and a CSS active-drop fallback otherwise. Context loss also switches to CSS.
- It pauses rendering when the nav is off-screen or the browser tab is hidden; `prefers-reduced-motion` disables continuous animation.
- By default the nav is silent (`sound={false}`).
- At browser widths up to 1340px, the existing mobile-menu icon shows the compact link drawer instead of attempting to cram a wide navbar into the left half of the centered GAZU header.

## Running on macOS

From the project root, preserve your existing private `.env` file (not included in the ZIP):

```bash
npm ci
npm run setup
npm run test:liquid-nav
npm run build --prefix frontend
npm run dev
```

Open `http://localhost:5173`. On desktop, test all pill destinations and keyboard arrow controls, then resize below 1340px to test the mobile drawer. Verify mobile, WebGL-disabled/fallback mode and reduced-motion mode. For the production UI, run the Docker build as in the existing project documentation.

**This is a frontend-only change.** No database records, product catalogue, authentication, payment or environment files are changed.

## Verification caveats

The isolated static/route tests and TSX transpilation checks run in the tool environment. An actual frontend production build requires installing npm dependencies locally. Do not consider a build or browser smoke test passed until it actually runs on your Mac. A browser screenshot was not produced here.
